# Owner-selected tool grants

The AI requests an Agent Session with selected tool names and device/Zone scope. The independently authenticated owner may review the request and select **exactly which tools to grant**, separately from the requested duration. The server persists `requestedTools` as the immutable request and `tools` as the effective owner-approved grant; existing records without `requestedTools` remain compatible.

Relay Admin defaults to **Requested only** (least privilege). The owner can add any combination of the **Read**, **Write**, **Delete**, **Execute** and **External MCP** tool groups, then use individual checkboxes to add/remove tools. **All current tools** simply checks the currently visible individual tool names; the UI submits an explicit fixed list and does **not** include tools introduced in later releases. The same is true of Read/Write/Delete/Execute/External MCP group presets. **The backend deliberately retains its original `tools: ["*"]` wildcard capability**, meaning all enabled tools now and in the future. This is not used by the UI All/group shortcuts. Existing owner-approved wildcard records keep their original dynamic meaning; an old MCP client or direct authenticated owner API may still request or approve a literal wildcard. Neither API compatibility nor old grants are silently rewritten. The original AI request is retained when available. The explicit grant preview indicates when the selection exceeds the AI's request. Empty or unknown tool grants are rejected by the Durable Object.

This feature broadens or narrows the permitted **tool set only**. It does not broaden the authenticated connector, Zone, devices or membership, and it does not change disabled local Agent capabilities. Only the owner-facing protected `/api/admin/agent-sessions/:id/approve` endpoint accepts `approvedTools`; the AI-facing MCP request endpoint cannot approve or update grants. An omitted `approvedTools` preserves previous request-only approval behavior.

Tool categories are defined in one shared allowlist, `worker/agent-session-tool-groups.ts`, consumed by both MCP request validation and owner approval validation. `test/owner-tool-grants.test.ts` covers broadening/narrowing, UI named-tool selection versus persistent backend wildcard, old approved wildcard compatibility, invalid grants and owner UI controls. `test/relay.test.ts` checks that authenticated owner changes flow through Worker to storage.
