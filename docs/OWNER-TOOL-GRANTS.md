# Owner-selected tool grants

The AI requests an Agent Session with selected tool names and device/Zone scope. The independently authenticated owner may review the request and select **exactly which tools to grant**, separately from the requested duration. The server persists `requestedTools` as the immutable request and `tools` as the effective owner-approved grant; existing records without `requestedTools` remain compatible.

Request syntax is intentionally explicit and least-privilege. `request_agent_session` accepts `tools:["read_file"]` when a path is known or a coherent narrow list such as `["workspace_info","list_directory","find_files","read_file"]` when exploring an unfamiliar workspace. For convenience, `tools:["read"]` captures the current **Read** group; `tools:["all"]` and omitted `tools` capture every currently known tool. These presets expand into concrete names **when the request arrives**, before persistence. A request containing `tools:["*"]`, a mixed shorthand (for example `["read","write_file"]`), or unknown/duplicate names is rejected. Future tools are never added automatically to a new grant.

Relay Admin defaults to **Requested only** and displays the exact snapshot. The owner may select any combination of **Read**, **Write**, **Delete**, **Execute** and **External MCP** tool-group shortcuts or adjust individual checkboxes. **All current tools** and each group shortcut expand only to current concrete names; the owner can narrow or explicitly broaden the requested scope. The model does not choose the duration or approve itself.

**Legacy migration boundary:** Previously approved `tools:["*"]` grants retain their stored **dynamic** behavior, including future enabled tools. They are not silently revoked, changed, or expanded into snapshots. New MCP requests and owner API approvals/edits **cannot** create a wildcard. A pre-upgrade pending wildcard request needs an explicit owner-selected list; an omitted `approvedTools` cannot create a new wildcard grant. For an already approved wildcard, the UI warns that an unchanged selection keeps the old grant; only a deliberate tool selection replaces it with explicit names. The owner may separately revoke or let existing grants expire.

This feature broadens or narrows the permitted **tool set only**. It does not broaden the authenticated connector, Zone, devices or membership, and it does not change disabled local Agent capabilities. Only the owner-facing protected `/api/admin/agent-sessions/:id/approve` endpoint accepts `approvedTools`; the AI-facing MCP request endpoint cannot approve or update grants. An omitted `approvedTools` selects the request-time explicit tool snapshot; it does not authorize a legacy pending wildcard.

Tool categories are defined in one shared allowlist, `worker/agent-session-tool-groups.ts`, consumed by both MCP request validation and owner approval validation. `test/owner-tool-grants.test.ts` covers broadening/narrowing, request-time snapshots, the Read preset, rejection of new wildcards, legacy approved and pending wildcard compatibility, and owner UI controls. `test/relay.test.ts` checks that authenticated owner changes flow through Worker to storage.
